## Рекомендований порядок виправлення

1. В ізольованій копії перевірити актуальну підтримувану версію Firebase CLI та lockfile з `npm view firebase-tools version`, `npm audit --json`, `npm ls ...`. Номер «останньої» версії не доводить виправлення.
2. Приймати підтримувані оновлення батьківських пакетів з указаними порогами, а не blind `npm audit fix --force`. Наразі audit пропонує firebase-tools@14.23.0 як breaking replacement; це саме по собі не доказ безпеки й може змінити функціональність.
3. Якщо upstream ще не виправлено, для trusted recovery використовувати напряму Admin SDK без Firebase CLI, а локальний CLI ізолювати від недовірених proxy/patterns. Це зменшення доступної поверхні, не усунення advisory з lockfile.
4. Перевірити запуск/завершення емуляторів, reload Rules, усі security тести, 201-record export/restore та повторний audit. Зафіксувати нові exact versions/paths до прийняття зміни.

У цій задачі major CLI/транзитивні пакети не замінені. Оплату, billing, Cloud Functions чи production не змінено.

Перед review-комітом повторний audit 04.10.2026 показав 7 high / 9 moderate (16 пакетів у звіті), ті самі 4 кореневі advisory. Раніше зафіксовано 7 high / 4 moderate; це попередній результат. Номери установлених пакетів і кореневі advisory у таблиці не змінилися. Production-only audit повторно: 0.
