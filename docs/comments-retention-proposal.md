# Зберігання та очищення: рішення й пропозиція

Погоджено: історичні резервні копії — приватний Google Drive, **30 діб від exportedAt**, ручне видалення кожного архіву й його доступних дублікатів, із датою видалення в журналі. Порядок ще треба налаштувати/перевірити за comments-backups-drive.md. Автоматичного очищення немає.

Решта строків нижче — **пропозиція, не погоджене правило й не активна процедура**. Їх не переносити в публічну політику як уже чинні без погодження та перевірки.

| Дані | Пропонований конкретний критерій | Дія після погодження списку |
|---|---|---|
| Pending | 30 діб від останнього updatedAt, без активного звернення/hold | Ручний перегляд; схвалити або погодити видалення. Не публікувати автоматично |
| Hidden із текстом | 90 діб від updatedAt, без активного спору/hold | Погодити очищення тексту/імені та відповідних непотрібних службових записів |
| Rate limits | 7 діб від lastSubmittedAt | Кандидат на видалення; це значно довше чинного 60-секундного інтервалу |
| Published та відповіді | Немає погодженого автоматичного строку; актуальність обговорення/запит автора | Індивідуальне рішення; не видаляти гілку за віком |
| Авторство й підтвердження | Поки потрібні відповідний коментар, звернення або захист прав | Видалення/знеособлення після окремої оцінки, не нескінченне зберігання за замовчуванням |
| Moderation | Поки потрібний відповідний запис або розгляд інциденту | Очищати лише погоджену пов’язану пару; provenance видалення не втратити |
| Блокування/Admin/Auth | Поки потрібні відповідний доступ, блокування чи акаунт | Окремий ручний перегляд/запит; цей cleanup не змінює Auth чи права |
| Tombstones, parent із відповідями | Збереження структури гілки та suppression | Не обираються автоматично; можливе подальше приватне знеособлення за окремим планом |
| Актуальний deletion register | Поки потрібний захист від відновлення відомих видалень та розгляд звернень | Окремий службовий строк; не стирати попередню історію через закінчення строку однієї копії |

Пропонований ручний цикл: раз на місяць перегляд непотрібних записів, без автоматичного запуску й автоматичного видалення. Для 30-денних копій — окремі нагадування на точну дату; щомісячний цикл її не замінює.

Після погодження строків: нова копія/актуальний register → явний agreed-retention.json із asOf/holds/погодженими days → `cleanup-plan.mjs` → конкретні шляхи/причини/кількості → окреме підтвердження → контрольоване ручне очищення → новий register/копія й full comparison. Published, holds, parents/replies і deletion provenance не видаляються автоматично. Видалення старої копії не видаляє живі коментарі; видалення живого тексту не очищає старі копії. Це два окремі списки й дії.

Інструмент dry-run не застосовує цю таблицю сам і ніколи не видаляє. Погодження лише backup-строку 30 діб не означає погодження pending/hidden/rateLimits.
